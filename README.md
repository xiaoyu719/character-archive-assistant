# 人物档案助手

用于 SillyTavern / TauriTavern 的酒馆助手脚本。给一点模糊设定，由 AI 补成人物草稿；审阅后存入已有世界书，玩家主动决定人物何时登场。

**[下载 v0.3.1 脚本](https://github.com/xiaoyu719/character-archive-assistant/releases/download/v0.3.1/character-archive.script.json)** · [版本与下载页](https://github.com/xiaoyu719/character-archive-assistant/releases/latest) · [备用直接下载](https://raw.githubusercontent.com/xiaoyu719/character-archive-assistant/main/character-archive.script.json)

## 安装

1. 使用已安装酒馆助手、支持脚本功能的 SillyTavern 或 TauriTavern。
2. 下载上面的 `character-archive.script.json`。如果备用链接只显示文字，请保存为这个文件名。
3. 在酒馆助手的脚本管理中，通过导入功能选择该 JSON。升级时替换或停用旧人物助手，只运行一份。
4. 启用脚本、打开角色聊天，点击右下角“人物档案”。

这是酒馆助手脚本 JSON，不是角色卡，也不是通过“扩展安装”粘贴仓库地址安装的扩展。不需要安装或修改数据库插件。

## 使用

- 选择已有世界书，输入例如“怕麻烦的游医”，点击生成。可参考当前角色卡和相关启用的世界书内容，参考有长度上限。
- 审阅和修改草稿后保存。初始生成两条关闭的条目：完整档案、内容为空的参与条目。
- 点击“启用角色并填入登场请求”，参与条目启用，请求填入聊天输入框，由玩家发送。不会自动发送或自行安排人物登场。
- 玩家选择不同放出层级，逐步增加参与条目中的设定。完整档案保持关闭；层级增加不是每轮自动投放一段消息。
- 保存到未绑定的书时会提示，需要自行绑定到当前角色或聊天才能参与对话。
- 格式失败时展开“本次生成原文”，可以修正后点击“从原文重新检查”，不会额外调用模型。原文只保留在当前窗口，切聊天会清空。

标题栏和入口支持拖动。具体宿主的显示和操作以实际版本为准；缺少必要接口时界面提示并阻止写入。

## 新聊天与删除范围

脚本在浏览器保存人物条目的世界书名、聊天身份、人物编号和完整条目名称。收到宿主的 `CHAT_CREATED` 新聊天通知后，删除同角色/群组此前聊天已登记的人物，保留当前聊天新建的人物。普通切换聊天不删除。

为清理早期版本遗留或丢失登记的条目，还会检查可用世界书，按本工具专用名称找回：

```text
TW-CharacterArchive-v1-ARCHIVE-
TW-CharacterArchive-v1-LIVE-
【人物档案·完整】
【人物档案·参与】
```

**没有身份标记的旧版专用条目会直接按名称删除，即使在其他世界书中。**有可识别身份时保留当前聊天和其他角色人物。手动“清理此角色人物及旧版遗留条目”也会删除当前聊天本工具的人物。用户普通条目和数据库前缀条目不属于本工具删除对象。

删除后会检查返回的条目编号并重读世界书；出错显示未完成。共用世界书中的实际条目删除后，旧聊天也会失去这些档案，聊天历史不会回滚。多本书删除可能部分完成。

登记保存在当前网站的浏览器存储中，不跨设备同步。清除网站数据后可按上述专用名称找回；如果登记、身份标记和原名称都丢失，就无法识别。请避免多个标签页同时写入人物。脚本晚于新聊天通知启动、通知缺失或中途切聊天时，自动清理可能无法完成，请查看运行记录并手动验证。

## 源码与本地验证

需要 Node.js 运行开发命令，用户导入脚本不需要安装 Node.js。

```sh
npm ci
npm run build
npm test
```

`build-standalone.cjs` 从源码生成根目录可导入 JSON；生成中间文件放在 `standalone-v0.3.1/`。`tests.cjs` 保留早期基础行为测试，`standalone.test.cjs` 检查当前独立管理和浮窗链路，`generation-format.test.cjs` 检查格式修复。测试使用模拟模型和世界书，不代替宿主实测。

运行时依赖是宿主提供的酒馆助手接口。没有远程脚本加载，也不需要数据库 API。`jsdom` 只用于开发测试。

接口和流程依据见 [PROVENANCE.md](PROVENANCE.md)。
